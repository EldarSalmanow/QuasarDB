# План задач QuasarDB (2026)

## Процесс и ветвление
- Базовая интеграционная ветка: stage/zero.
- Вся работа ведется в feature-ветках с PR в stage/zero.
- Имена веток: <type>/<ticket>-<short-desc> (пример: feature/STORAGE-3-b-star-index).
- Коммиты: Conventional Commits с номером задачи в квадратных скобках.
- Обязательные проверки перед merge: build, clang-format, clang-tidy, tests.

## Стек и инструменты
- C++20, CMake 3.16+, Ninja.
- Зависимости через Conan: nlohmann/json, GTest, taywee/args.
- Инструменты: clang-format, clang-tidy, Dev Container (Ubuntu 22.04).

## Текущее состояние
- INFRA-1: в основном сделано (таргеты CMake, Conan, README, заглушки main.cpp).
- INFRA-4: в основном сделано (devcontainer, clang-format, clang-tidy), но нет интеграции clang-tidy и ASAN в CMake.
- STORAGE-1: pager реализован с тестами.
- STORAGE-3: B*+ дерево реализовано с тестами.
- Остальное: не реализовано (заглушки или отсутствие кода).

## Межкомандные зависимости
- API.md (INFRA-2) нужен до начала полноценной работы клиент/сервер.
- Лексер/парсер/грамматика (PARSER-1..3) нужны до семантики и исполнения.
- Иерархия БД (STORAGE-2) и таблицы (STORAGE-4) нужны до RBAC и логирования.
- Очередь задач (ASYNC-1) нужна до API статуса (ASYNC-2).
